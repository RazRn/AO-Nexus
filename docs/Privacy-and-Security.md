# Privacy and security in AO Nexus

This describes the implementation in this source checkout, not a claim that software or a game server is risk-free. An overview is also available offline under **Settings → General → Privacy & security**.

## Passwords and account data

- Password saving is optional per account. New accounts default to asking at each launch action. An entered password can serve several selected characters on that account in the same action.
- Saved passwords use Windows DPAPI with `CurrentUser`. Records are bound to the account ID, username and configured login endpoint. They live in `%LOCALAPPDATA%\AONexus\Credentials`, separately from the profile JSON.
- Disable **Remember password** in Edit account to remove that account's saved copy. **Settings → Accounts → Forget passwords** removes all Nexus saved copies. **Update saved password** changes the local copy, not the game account's password.
- Passwords exist in process memory during use. Nexus passes launch requests through the backend's redirected standard input, not command-line arguments or a plaintext request file. Managed strings cannot be guaranteed to disappear immediately from memory.
- DPAPI does not defend against malware running as the same Windows user, an administrator, or a compromised running game/backend. It is local storage protection, not transport encryption. The bundled backend uses the game's existing authentication protocol; Nexus does not add TLS to game login. Trust the selected server and game installation before entering credentials.
- Account names, usernames, character IDs, server addresses, local paths and team presets in `AONexus.json` are **not encrypted**. The activity log and update history can contain names and paths. The separate diagnostics log and crash reports replace them with codes before writing to disk (see [Diagnostics and problem reports](#diagnostics-and-problem-reports)). Nexus does not automatically upload profiles, credentials, logs or crash reports and has no analytics integration.

## Connections made by the app

For a fresh profile, the setup wizard runs before optional news, health or GitHub checks. Finish saves the selected preferences; Skip leaves these features off. Adding accounts during setup does not log in, request passwords or contact a game server. Existing/imported profiles retain their prior choices and are not forced through setup again.

Remote services can see your public IP address, request time and normal protocol metadata. Windows DNS/proxy/network configuration can also affect these connections. The launcher does not run a public web server, Discord webhook sender or port scan. Custom servers start with a login connection check; you can also configure world/zone and chat checks under **Settings → Accounts → Manage health checks**. A server name alone does not attach a custom server to another server's public report.

## Diagnostics and problem reports

Optional **client exit reports** are separate from Nexus's own crash reports. They retain the last 120 samples per tracked client, a bounded summary of the period Nexus observed that client (state counts, plugin coverage, peak memory and maximum observed gaps/reply times), and up to 20 saved exits under `%LOCALAPPDATA%\AONexus\ClientReports`. Reports also record monitoring settings and snapshot availability or rejection reasons. Every observed exit can create a report, including a normal logout. Names use consistent aliases across each exported ZIP; process IDs, exact start times, timestamps and executable versions remain. Duplicate saved exits are omitted when the same evidence is already included. Saving a diagnostic ZIP adds matching, allowlisted Windows Application error/hang fields, without raw event XML, passwords, chat, personal paths or memory dumps. Nothing is automatically uploaded. Read `report-summary.txt` for measurement coverage. Process samples alone do not prove responsiveness. Stale measurements are identified separately from a stopped update callback or missing IPC reply; none of these alone proves a crash or server packet loss. See [client measurements and reports](Client-Monitoring.txt).

The diagnostics log helps explain problems that are hard to reproduce, such as one character in a team failing to log in. It records activity-log messages, login steps reported by the bundled backend (start, time to the character window, client exit codes, timeouts and the window state they stopped in), Game GUI and news errors, login stages reported by the bundled login handler from inside the game client (fixed stage names and numbers only, sent over a private pipe restricted to your Windows user), the text of standard Windows dialogs a game client shows while logging in, unexpected exceptions with stack traces, and a short environment summary at each start: Nexus, Windows and .NET Framework versions, administrator status, display scaling, memory, the number of running game clients, counts of accounts, characters and presets, server limits, game client file versions and folder types (for example *OneDrive* or *Program Files*).

Before anything is written, Nexus replaces logins, account labels and IDs, character names and IDs (also inside folder names such as `Char123456789`), team names, custom server names and addresses, game and Prefs folders, your Windows user and computer name, profile and OneDrive paths and e-mail addresses. Codes such as `Char-3fa2c1` are derived with a random key stored only on your PC (`anonymisation.key`), so the same character keeps the same code across sessions but cannot be traced back from a shared report. Passwords and the backend's request are never logged. The public addresses of the built-in servers are kept, because they identify the server type rather than you. Text produced by game clients can include names Nexus does not know, such as other players; review the preview before sharing.

Reports are created only with **Report a problem…**, where you can review the full text first. A report also lists the antivirus products registered in Windows Security Center, because security software can block the login helper. Turning off **Keep an anonymised diagnostics log** under Settings → Updates stops recording and deletes the log, crash reports and key; **Delete diagnostics now** does the same while keeping the log enabled.

## Update verification and recovery

The updater accepts stable releases from `RazRn/AO-Nexus`, requires a newer version, checks the downloaded ZIP against GitHub's SHA-256 metadata, validates the included executable checksum and assembly version, bounds download/extraction sizes, and extracts only the expected executable entry. HTTPS certificate validation is not bypassed. These checks depend on GitHub and the release account; they are **not an independent publisher signature** and do not protect against a compromised maintainer account publishing malicious code.

Installation requires confirmation and write access to the app folder; it does not request administrator elevation. A staged helper waits for the original process, rechecks executable hashes, and atomically replaces the executable with a backup. Failure to start the replacement triggers restoration. Launch success is not a guarantee that every feature works. After startup, cleanup retains one previous Nexus executable for manual recovery. Your game windows, profile and credentials are not part of replacement.

## Local files and retention

Game GUI templates contain only selected supported preferences, never the whole account folder. The optional Macros component copies a character's text macros, which can contain character names. Script copies handle only plain text files in an installation's `scripts` folder and refuse program, binary and linked files. Macros and scripts are never added to diagnostics or problem reports. Templates and backups can contain character labels, local paths and personal GUI settings. They are not encrypted or uploaded automatically. Skin imports reject executable/script entries and unsafe archive paths; the author download's optional command script is omitted and never executed. Package hashes identify reviewed contents, not a publisher signature. Data validation cannot guarantee compatibility or appearance in every game client.

GUI changes require confirmation and affected clients must exit before preference writes. Nexus can ask to relog known clients via `/quit`, waits for actual process exit, and rechecks before writing. Unknown clients block the change. Character-only operations match affected character identities and preference paths. For shared skin changes, an unverified Prefs-to-game mapping can expand the confirmation to all identified running AO clients. Cancellation cannot undo an already completed logout. File transactions back up changes and attempt rollback on failure; unresolved recovery data is preserved. Do not manually launch affected clients or edit their preferences during an operation.

| Location | Retention |
| --- | --- |
| `%LOCALAPPDATA%\AONexus\AONexus.json` and profile recovery files | Saved settings; preserved across updates. |
| `%LOCALAPPDATA%\AONexus\Credentials` | Encrypted passwords until removed through account settings/Forget passwords. |
| `%LOCALAPPDATA%\AONexus\GuiLayouts` | Templates until deleted. Latest 10 completed layout backups per character, 10 completed script backups per installation (`ScriptBackups`) and 10 successful skin-selection backups per Prefs installation; interrupted/unrecognized recovery records remain for inspection. |
| `Gui` beside the game's `Prefs` folder | Installed custom skins remain for reuse. Identical imports reuse matching contents. Temporary download/import staging is cleaned on success or failure. Original game skin files are not replaced. |
| `%LOCALAPPDATA%\AONexus\News` | Bounded per-source news cache, reused for offline fallback. |
| `%LOCALAPPDATA%\AONexus\Runtime` | Verified, content-addressed bundled login engine. Reused when the payload is unchanged. Old runtime versions are preserved because open game clients may still use their native components. |
| `%LOCALAPPDATA%\AONexus\Monitoring` | Verified, content-addressed AOSharp measurement plugin and helper, extracted from the portable EXE when needed. Existing profile paths stay valid across updates. |
| `%LOCALAPPDATA%\AONexus\Telemetry` | Per-process measurement snapshots with timestamps and counters, including a recognized cast-while-falling issue code, grouped report count and confirmation flag. No chat text, usernames, character names or game credentials. The plugin replaces its snapshot twice per second and records explicit unloading when possible. |
| `%LOCALAPPDATA%\AONexus\ClientReports` | Optional client-exit reports, newest 20 retained. Disabling collection stops new reports; previously saved files remain. |
| `%LOCALAPPDATA%\AONexus\Diagnostics` | Anonymised `diagnostics.log` capped at 2 MB (oldest entries trimmed first), the 20 newest crash reports in `Crashes`, and the pseudonym key. Removed when diagnostics are turned off or deleted in Settings → Updates. |
| In-memory activity log | Current session only. Default 5 MB of UTF-8 text; adjustable 1–100 MB under Settings → Updates. Oldest entries are discarded first. The searchable window shows the same retained log. **Clear log** asks for confirmation and clears the entire session log, including entries hidden by a search; it does not clear the separate update history. This is a text limit, not a total RAM limit. |
| `%LOCALAPPDATA%\AONexus\Updates\update-history.log` | Same configurable cap per log, newest entries retained; no accumulating rotated copies. Lowering the cap trims existing history. |
| `%LOCALAPPDATA%\AONexus\Updates\<GUID>` | Download/extraction failures are cleaned immediately where possible. Completed stages are cleaned after the updated app starts. Abandoned stages are retried on startup once older than 24 hours; failed-update details are also recorded in bounded history. Locked stages are skipped and retried next startup. |
| `AONexus.exe.previous-<GUID>` next to the app | One most recent previous executable is retained per installation; older verified Nexus backups are removed on startup. |
| `%LOCALAPPDATA%\AONexus\Sessions` | Nexus client tracking and session coordination; no game passwords. |

Cleanup only removes recognized updater-owned files in direct GUID directories, rejects reparse paths, does not recurse through unknown subdirectories, and respects the active updater lock. Unknown files are left alone. It does not modify game installs, Prefs or other applications. A folder inaccessible to Windows cannot be guaranteed to be cleaned until access is restored.

For complete removal, close Nexus, disable Start with Windows, finish/close game clients using its runtime, then remove the installation and the Nexus-specific AppData folder yourself. Keep a private profile backup if wanted. Local filesystem deletion does not erase external backups, cloud copies or another application's stored credentials.
