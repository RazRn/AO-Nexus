Guard
The monitor observes accepted movement on the existing AOSP channel. It
does not increase correction range or change ManagerSync settings. A fresh,
accepted move from a visible sender arms the follower. Same-frame game
positions are checked every 200 ms, avoiding cross-client snapshot skew.
Warning: separation >= max(8 m, sync limit + 3 m) for 2 seconds.
Stop: continuous separation for 4 seconds, distance >= max(15 m, limit + 8 m),
and still moving. Ordinary FullStop is queued once, followed by one rally
message after the client confirms it stopped. Alarm events reach Nexus even
with Control Panel closed; Windows notification/sound settings still apply.
Foreground/manual control, zoning, combat/casting, navigation, death, disabled
sync, channel changes and absent visible sender disarm the guard. A new
accepted movement is needed after a 3-second grace. Thus this is protection
for confirmed AOSP movement run-off, not a universal movement watchdog.
A sample gap above one second starts a new observation interval; a stalled
game loop is not evidence of continuous separation. Episode latches prevent
duplicate warnings/stops. No promise of zero false positives is made.

Rally
/nexus-rally sends a location popup to the confirmed Team channel. The leader
and followers can use it. Automatic messages are once per stop episode, and
all messages have a 10-second per-client limit. Missing channel information
is explicit; no fallback to Global/Vicinity. Clicking Mark location on map
runs the ordinary /waypoint command, not automatic walking or navigation.

Andromeda and 3256 874, and the client confirmed map/compass upload. Unicode

Separate post-zone discrepancy discovered (not repaired in this test)
TEAMVIEW from all six says Ready=true, Leader=0, Members=[], while the actual
Overwhelming Team window visibly contains all six and the monitor's native
GUI query says IsTeamLeader=true. NexusAutoTeam still relies on Team.IsInTeam,
Team.IsLeader and Team.Members, whose member-list implementation returns an
empty list when the engine IsInTeam query is false. This can affect future
leader recovery after zoning. The sync guard uses accepted AOSP movement and
visible characters independently, so its Watching state remains valid.
Do not interpret this false empty report as a real team disband or issue
automatic invites based on it. A consistent native-backed roster read is
needed; changing only the leader boolean would leave Members incomplete.
