SOURCE AND DEPENDENCY REVIEW
Reviewed src/PluginHost/NexusPluginHost.cs, build/Build-PluginHost.ps1 and the
PluginHostClient in src/Launcher/AOSharpPack.cs. The host is an x86 .NET
Framework executable compiled against framework libraries. It dynamically
loads EasyHook and AOSharp.Bootstrap from the user's selected AOSharp folder.
The launcher extracts the embedded helper into a checksum-specific local
folder and starts it without a shell. The helper keeps the bootstrap connection
alive so restarting the Nexus window does not unload plugins in open games.

Injection is explicit in the code: EasyHook.RemoteHooking.Inject loads the
AOSharp bootstrap into the requested game process. The helper checks process
name, PID/start time and the existence of selected DLL paths. Its Nexus-facing
named pipe has a current-user ACL. These are useful constraints, not a security
sandbox or binary publisher verification. Local plugins execute trusted code;
the selected third-party runtime controls its own behavior.

No Defender configuration changes, credential collection, HTTP client, service
installation or Windows startup registration were found in this helper source.
This statement is limited to the helper. The parent launcher implements the
optional Windows startup setting in DesktopLifetime.cs; the login backend
handles credentials and injects its separate LoginHandler using Reloaded.Injector.
Third-party EasyHook includes a service executable, so a blanket claim that the
whole application/dependency chain cannot use services would be incorrect.

Accessible selected-runtime bootstrap IL was inspected without executing it:
it references EasyHook, AOSharp.Common, Serilog, Serilog.Sinks.File, Newtonsoft.Json
and framework libraries, and contains the expected assembly loading and IPC
paths. This focused inspection is not a new exhaustive scan of the 64 plugins.

RELEASE REQUIREMENT
build/Package.ps1 first checks the exact launcher with Verify-DefenderRelease.ps1.
It requires active antivirus/real-time/behavior monitoring, archive scanning,
signatures no older than 24 hours, no matching active detection, a non-excluded
artifact, a successful custom scan, and identical SHA-256 before/after scanning.
New matching detections block even when the scanner reports successful remediation.
The completed ZIP is scanned before replacing the named release archive.
Failure leaves any previous named archive untouched; do not treat an older ZIP
as approval for a newer build. Reports under logs are local evidence only.

A clean static scan does not resolve a behavioral alert. Package.ps1 also
requires -DefenderRuntimeReview pointing to a completed copy of

for the exact executable hash, with Defender enabled on a test machine, covering
